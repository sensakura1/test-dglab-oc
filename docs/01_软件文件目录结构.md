# 《OC 设定写作督促工具》软件文件目录结构

## 1. 目录设计目标

本目录结构用于指导后续编码实现，目标是让界面、核心业务、系统监测、设备适配、配置、日志和测试彼此分离，便于逐模块开发和替换技术栈。

## 3. 目录说明

### 3.1 `docs/`

存放需求、总开发文档和模块开发文档。该目录不参与程序运行，但作为开发和验收依据。

### 3.2 `src/main/`

桌面应用主进程入口，负责程序启动、生命周期、IPC 注册、全局快捷键、后台服务初始化。

核心职责：

- 启动应用。
- 初始化 `AppController`。
- 注册急停快捷键。
- 建立 UI 与核心模块之间的通信。

### 3.3 `src/core/`

核心业务逻辑目录。该目录应尽量不依赖具体 UI 框架，便于单元测试。

子目录职责：

| 目录 | 职责 |
| --- | --- |
| `config/` | 配置加载、保存、校验、默认值 |
| `monitor/` | 活跃窗口监测、输入活跃度监测 |
| `scope/` | 写作范围、分心范围、忽略范围匹配 |
| `session/` | 专注周期、计时、状态机 |
| `trigger/` | 触发规则、冷却、次数限制、强度计算 |
| `safety/` | 急停、锁定、限幅、安全模式 |
| `device/` | 郊狼设备适配器和模拟设备 |
| `log/` | 日志记录和隐私脱敏 |
| `event/` | 内部事件总线和事件类型 |
| `utils/` | 通用工具函数 |

### 3.4 `src/renderer/`

前端界面目录，负责用户交互和状态展示。

核心页面：

- `dashboard.tsx`：主控制台。
- `settings.tsx`：配置页面。
- `logs.tsx`：日志页面。

### 3.5 `assets/`

存放图标、图片和打包资源。

### 3.6 `config/`

存放示例配置文件。真实用户配置建议写入用户数据目录，不建议直接写入源码目录。

### 3.7 `logs/`

本地日志目录。开发环境可保留 `.gitkeep`，实际日志文件不应提交到版本库。

### 3.8 `tests/`

测试目录。

- `unit/`：单元测试。
- `integration/`：跨模块集成测试。
- `fixtures/`：测试配置样例。

### 3.9 `scripts/`

开发、测试、构建、打包脚本。

## 5. 配置与日志文件建议位置

开发环境：

```text
config/config.example.json
logs/app-dev.jsonl
```

生产环境：

```text
%APPDATA%/OCWritingFocusCoyote/config.json
%APPDATA%/OCWritingFocusCoyote/logs/app.jsonl
```

注意：

- 用户真实配置不应提交到仓库。
- 日志需要默认脱敏。
- 配对 token 不得出现在普通日志中。

---

## 6. 命名规范

- 源码文件使用英文小驼峰，例如 `triggerEngine.ts`。
- 类型文件使用模块名加 `Types`，例如 `triggerTypes.ts`。
- 文档文件可使用中文命名，保持编号顺序。
- 测试文件使用 `.test.ts` 后缀。
- 配置字段使用 JSON 常见蛇形命名或代码层统一转换，避免混用。
